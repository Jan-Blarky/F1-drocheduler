# F1 drocheduler

Телеграм-бот, который сам вешает расписание гоночного уикенда в закреп группы
и напоминает про гонку накануне вечером. Крутится на GitHub Actions, платить
не за что.

## Что и когда шлёт

| Сообщение | Когда | Закреп |
|---|---|---|
| Анонс уикенда: квалификации, спринты и гонки Ф1/Ф2/Ф3 | понедельник 10:00 по Израилю на неделе этапа | да, висит до конца сезона |
| Напоминание о гонке Ф1 | 19:00 по Израилю накануне дня гонки | нет |
| Отсчёт до нового сезона | после финального этапа | да, перед этим снимаются все старые закрепы |

Время всегда израильское, в скобках — местное на трассе.

Гонки бывают не только воскресные (Баку-2026 — суббота), поэтому все моменты
отсчитываются от реального дня гонки по израильскому календарю, а не от
«воскресенья». Для Лас-Вегаса гонка местно субботняя, но у нас воскресная —
напоминание уходит в субботу вечером.

## Откуда данные

JSON-календари проекта [sportstimes/f1](https://github.com/sportstimes/f1)
(движок f1calendar.com) — отдельно Ф1, Ф2 и Ф3, времена в UTC. Ф2 и Ф3 приезжают
не на каждый этап и нумеруют раунды по-своему, поэтому они привязываются к этапу
Ф1 по пересечению дат сессий.

Названия этапов и трасс в исходных данных ненадёжны, поэтому берутся из
`events.py` — там же таймзоны трасс. **Раз в год этот файл нужно дополнять
новым сезоном.** Если раунда там нет, бот не падает: подставляет название из
источника и пишет `WARNING` в лог Actions.

## Настройка

1. Бот создан через [@BotFather](https://t.me/BotFather), добавлен в группу
   администратором с правом «Закреплять сообщения».
2. В `Settings → Secrets and variables → Actions` заданы секреты:
   * `TG_BOT_TOKEN` — токен от BotFather;
   * `TG_CHAT_ID` — id группы (отрицательный, вида `-100…`).

## Локальный запуск

```bash
python3 bot.py --preview 14              # показать сообщения для этапа 14
python3 bot.py --dry-run                 # что бот сделал бы прямо сейчас
python3 bot.py --dry-run --now 2026-09-07T10:00   # ...в заданный момент
```

Боевой запуск читает `TG_BOT_TOKEN` и `TG_CHAT_ID` из окружения.

## Как не задваивается

Всё отправленное отмечается в `state.json`, который workflow коммитит обратно в
репозиторий. Крон запускается шесть раз в сутки — лишние запуски ничего не
делают, а пропущенный (упавший раннер, задержка Actions) догоняется следующим,
пока не истекло окно: 12 часов для анонса и до старта гонки для напоминания.
